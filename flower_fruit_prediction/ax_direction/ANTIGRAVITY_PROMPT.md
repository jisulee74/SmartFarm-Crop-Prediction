1. 성능 및 오차 분석
2. AX 추가 데이터 구축 방향
3. As-Is/To-Be 검증 계획과 KPI

먼저 다음 폴더의 확정 분석 산출물을 읽어줘.
`AXData/ax_catalog_experiments/analysis/20260914_ax_direction/`

## 성능 및 오차 분석

- 작물과 예측 타깃(1·2·3화방·1~3화방 합계), evaluation split을 선택한다.
- 선정 모델·입력변수군·변수 수, RMSE·MAE·R²·CCC, seed SD, 표본 수, 시설 수를 보여준다.
- `baseline_performance.csv`의 선정 모델과 현재값 유지 기준, 진단용 0 예측 기준을 비교한다.
- validation으로 확정된 모델은 `selected_models.csv`를 기준으로 한다. test 성능이 더 좋은 모델로 자동 교체하지 마라.
- `error_strata.csv`에서 시설·작기·작기 경과일·직전 조사 간격·다음 실제 조사 간격·변화 구간·양수 여부·입력 결측별 결과를 조회한다.
- 표본 비율과 제곱오차 비중을 함께 표시해 오차 집중과 표본 부족을 구분한다.
- `crossed_error_strata.csv`는 시설·경과일·간격이 겹친 결과를 확인하는 상세 표로 제공한다. 상관을 인과로 표현하지 마라.
- N<30은 소표본 배지, 미정의 R²는 “미정의”, 결과 없음은 “미평가”로 표시한다. 0으로 대체하지 마라.
- 미래 정답으로 나눈 변화/양수 구간과 다음 실제 조사 간격은 “사후 진단”으로 표시한다. 실시간 사전 경보처럼 보여주지 마라.
- 주요 관측 근거는 `target_diagnosis.csv`와 보고서 01에 있다. 타깃별 인사이트와 근거 표를 연결한다.
- 5개 seed의 지표 평균과 예측 평균의 앙상블 지표는 다르다. 저장된 기준 지표를 임의로 다른 집계 방식으로 바꾸지 마라.
- 시설/작기 필터를 적용한 신규 지표를 계산하면 “조회 표본 기준 재계산”이라고 표시하고 전체 평가 지표와 구분한다.
- 실제값·예측값 그래프를 연결하려면 `selected_predictions.parquet`를 쓴다. `target_id`는 예측 과제 ID, `target`은 실제 개수다. row_id와 seed로 대응시키고 target_date를 그래프의 예측 대상 날짜로 쓴다.
- 시계열에서 seed를 섞어 행 수를 5배로 계산하지 마라. seed 하나를 선택하거나 “seed별 예측 평균(참고)”임을 명시한다.

## 변수 범주 비교

- 기존 변수군 선택 화면이 있다면 `registered_categories.csv`와 `all_group_validation_metrics.csv`로 실제 등록 조합을 연결한다.
- 범주를 A·B·C 3개로 제한하지 마라. 실제 범주 수·이름과 조합은 데이터에서 읽는다.
- `paired_category_comparisons.csv` 또는 `category_effect_summary.csv`로 범주 하나를 추가한 조합 비교를 보여준다.
- 이 비교는 validation, 동일 모델/평가 표본, 각 조합 별도 튜닝 결과다. 인과 효과나 확정된 변수 중요도로 표현하지 마라.
- `model_comparison.csv`의 test 결과는 모델별 선정 변수군에만 존재한다. 다른 조합의 test 결과를 생성하지 마라.

## AX 추가 데이터 구축 방향

- `hypotheses.csv`의 H01~H07을 카드/표로 제공한다.
- 우선순위, 관측 근거, 개선 가설, 추가/기존 후보 항목, 검증 방법, KPI, 상태를 구분한다.
- “확인된 현상”과 “미검증 가설”을 분리한다. 적과/수확이 성능 저하 원인으로 확인됐다거나 AX 데이터 효과가 이미 입증됐다고 표현하지 마라.
- `ax_field_schema.csv`에서 항목별 타입·단위·출처·주기·연결 키·가용 시각 규칙을 펼쳐 볼 수 있게 한다.
- 기존 미활용 생육 변수 활용 과제와 신규 AX 수집 과제를 구분한다.

## As-Is/To-Be 검증 계획과 KPI

- `comparison_arms.csv`의 B0/B1/B2/A1/A2/A3/ABL을 비교 흐름으로 표시한다.
- 현재 데이터의 As-Is 결과와 향후 AX 효과 검증 계획을 구분한다. To-Be 성능은 “미실험” 상태로 표시하고 가상 실측값을 만들지 마라.
- `kpi_planning_reference.csv`의 목표는 현재 기준에 10%/15%를 적용한 “협의 전 기획 예시”다. 확정 목표나 달성 값으로 표시하지 마라.
- 새 코호트에서 기존 입력과 추가 입력을 같은 조건으로 다시 비교한다는 점을 설명한다.
- 현재 holdout는 이미 확인된 자료로 이번 분석은 진단용이며, seed SD는 시설 일반화 신뢰구간이 아님을 필요한 위치에 짧게 표시한다.

## 구현과 검증

- `dashboard_bundle.json`은 브라우저 연동용 요약 테이블 묶음이다. 큰 parquet 파일은 서버에서 필요한 범위만 읽어 제공해라.
- 기존 서버와 프런트엔드 구조를 확인하고 필요한 최소 변경으로 구현한다. UI에 원시 파일 경로나 구현 설명을 과도하게 노출하지 마라.
- 근거 CSV/Excel 다운로드와 분석 문서 열기를 제공한다.
- 주 타깃: 토마토 합계와 딸기 2화방을 포함해 실제 수치가 원본 표와 일치하는지 검증한다.
- 최소 검증: 8개 타깃 전환, test/validation 분리, 미정의 지표, 소표본 표시, 선택 필터, To-Be 미실험 표시, 시계열 row 정합성, 기존 화면 회귀 확인.
- 기준 예시: 토마토 합계 test RMSE 약 0.896866, 유지 기준 약 0.740912. 딸기 2화방 test RMSE 약 1.494445. 이를 뒤집어 “모든 타깃 개선”으로 요약하지 마라.
- 수정 파일, 실행 방법, 검증 결과와 제한 사항을 마지막에 설명해줘.
