# 공통 회귀 모델 개편 계획 v1.3 수정안

## 요약

기존 v1.2를 복사해 `AXData/plan/화방수·착과수 공통 회귀 모델 개편 계획_v1.3.md`로 만들고, 기존 문서는 보존한다. 데이터 보호·leakage·블록·seed·Test 정책은 유지하며 아래 네 영역과 연관 절·산출물·테스트만 일관되게 수정한다.

## 핵심 변경

### 1. 변수군 선택과 튜닝 분리

Train 내부 CV를 두 단계로 나눈다.

1. `feature_set_selection`
   - 모든 모델에 YAML로 고정한 단일 기준 하이퍼파라미터 사용
   - 화방수 2개 고유 변수군과 착과수 순차 전진 후보 비교
   - MLP·TabM은 seed 42·52·62 평균 사용
   - 이 단계에서는 grid 탐색 금지
2. `hyperparameter_tuning`
   - 확정된 공통 변수군 하나에서만 모델별 제한 grid 수행
   - 동일한 Train 내부 3-fold 사용
   - fold별 best epoch/iteration 중앙값을 이후 고정 정책으로 저장
3. 고정 변수군·튜닝 결과로 전체 Train을 학습하고 외부 Validation에서 학습모델을 비교한다.

Section 7.1과 실행 흐름을 `품질 필터 → 기준 설정 변수군 선택 → 공통 변수군 확정 → 확정 변수군 grid tuning → 외부 Validation` 순으로 변경한다. 산출물도 `internal_cv/feature_set_selection/`과 `internal_cv/hyperparameter_tuning/`으로 분리한다.

### 2. 상관 중복 제거를 greedy 방식으로 변경

Connected component 방식은 제거한다.

- 의미 그룹별 변수를 대표 우선순위로 정렬한다.
- 첫 미처리 변수를 대표로 유지한다.
- 해당 대표와 직접 Spearman 절대값이 임계값 이상인 변수만 제거한다.
- 제거되지 않은 다음 변수를 새 대표로 선택해 반복한다.
- A–B와 B–C가 높더라도 A–C가 임계값 미만이면 C는 A 때문에 제거되지 않는다.
- 모든 제거 변수는 자신을 대체하는 대표와 직접 임계값 이상의 상관관계를 가져야 한다.

`correlation_clusters.csv`는 실질적으로 greedy 그룹을 기록하며 다음 열을 포함한다.

- `representative`, `removed_feature`
- `direct_abs_spearman`, `threshold`
- 양쪽 원천·의미 그룹
- 대표 우선순위 근거
- 의미적 동일성 판단
- `removed`, `high_correlation_retained`, `manual_review_required` 상태와 사유

### 3. 변수군 선정 기준 통일

모델 간 RMSE 크기를 정규화하기 위해 각 모델의 `individual_history` CV RMSE를 기준값으로 고정한다.

```text
normalized_rmse(feature_set, model)
  = cv_rmse(feature_set, model) / cv_rmse(individual_history, model)

normalized_mean_cv_rmse(feature_set)
  = mean(normalized_rmse over five learning models)
```

순차 전진 규칙은 다음으로 통일한다.

- 주 기준: `normalized_mean_cv_rmse` 최소화
- 블록 채택:
  - 현재 변수군 대비 정규화 점수가 1% 초과 개선
  - 5개 모델 중 최소 3개에서 raw CV RMSE가 악화되지 않음
- 채택 가능 블록이 여러 개면 정규화 점수가 가장 낮은 블록 선택
- 모든 활성 블록의 `full`도 한 번 평가
- 최종 후보의 정규화 점수가 최저값 대비 1% 이내이면 평균 rank 적용
- 이후 평균 CV MAE, 변수 수 순으로 결정

평균 rank는 주 선택 기준에서 제외하고 1% 동률권 tie-break에만 사용한다.

### 4. Persistence를 baseline으로 분리

외부 Validation의 선택 대상은 다음 5개 학습모델로 제한한다.

- Poisson Regression
- Random Forest
- CatBoost
- MLP
- TabM

Persistence는 동일 Validation 행에서 계산하지만 모델 선정 순위에는 넣지 않는다. 최종 학습모델이 Persistence보다 나쁘더라도 차선 학습모델로 바꾸거나 Persistence를 “최종 모델”로 지정하지 않고, “학습모델이 baseline을 넘지 못함”으로 결론 낸다.

학습모델 선택 규칙은 다음과 같다.

1. Validation RMSE
2. 최저 RMSE 대비 1% 동률권이면 MAE
3. MAE도 최저값 대비 1% 이내이면 측정된 Validation 추론시간
4. 이어서 직렬화된 모델 크기
5. 이어서 runtime dependency·저장 artifact 수로 기록한 구현 복잡도
6. 완전히 같으면 모델명 오름차순으로 재현성 있게 결정

추론시간은 동일 장치·동일 Validation frame에서 5회 warm-up 후 30회 반복의 중앙값으로 측정한다. Persistence를 포함한 고정 복잡도 서열은 삭제한다.

Test에서는 다음 두 대상을 동일 row key로 각각 한 번 평가한다.

- Validation에서 확정된 최종 학습모델
- 별도 Persistence baseline

기존 네 Test 산출물 명칭은 유지하고, manifest에 `selected_learning_model`, `persistence_baseline`, `baseline_beaten_on_validation`, `baseline_beaten_on_test`를 분리 기록한다.

## 연관 문서·인터페이스 수정

- `selection.py` 책임을 `select_feature_set_with_fixed_configs()`, `tune_models_on_selected_features()`, `select_learning_model_on_validation()`으로 명확히 분리한다.
- YAML에는 `feature_selection_baseline_params`와 `tuning_grid`를 별도 키로 둔다.
- 실행 상태를 `internal_feature_selection → internal_tuning → external_validation → freeze → final_fit → test_once`로 변경한다.
- v1.3 경로·진입점·artifact root 이름을 모두 `v1_3`으로 갱신한다.
- v1.0 대비 변경 요약에는 이번 네 변경을 추가하고, v1.2의 connected component·평균-rank 주 기준·Persistence 후보 표현은 남기지 않는다.

## 테스트 및 수용 기준

- 변수군 선택 단계에서 grid 조합이 호출되면 실패하는 테스트
- 공통 변수군 이외의 변수군에 tuning trial이 생성되지 않는 테스트
- A–B=0.95, B–C=0.95, A–C=0.70에서 A와 C가 모두 유지되는 greedy 회귀 테스트
- 모든 제거 변수가 대표와 직접 임계값 이상인지 검증
- 정규화 평균 RMSE, 1% 개선, 3/5 비악화, rank·MAE·변수 수 tie-break 테스트
- Persistence가 Validation 1위여도 최종 학습모델이 5개 학습모델 중에서 선정되는 테스트
- 학습모델이 Persistence를 넘지 못한 결과가 manifest와 보고서에 그대로 기록되는 테스트
- Test 산출물이 최종 학습모델과 Persistence 두 종류뿐인지 검증

## 유지되는 기본값

- 화방수·착과수 데이터, row key, leakage 제외 목록과 기존 split은 변경하지 않는다.
- 상관 임계값은 화방수 0.90, 착과수 동일 의미 센서 파생변수 0.95를 유지한다.
- 변수군 선택 DL seed는 42·52·62, 최종 비교와 Test는 42·52·62·72·82 ensemble을 유지한다.
- Test는 tuning, early stopping, 모델·seed 선택에 사용하지 않는다.
- 코드·패키지 설치·모델 학습·실험은 문서 작성 작업에 포함하지 않는다.
