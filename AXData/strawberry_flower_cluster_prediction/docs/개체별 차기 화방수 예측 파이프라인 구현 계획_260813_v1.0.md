# 개체별 차기 화방수 예측 파이프라인 구현 계획

## Summary

`(user_id, sample_num)`별 현재·과거 생육정보로 동일 개체의 다음 조사 시점 `fruit_cluster_num`을 예측한다. 93개 후보 변수를 생성하고, Train 데이터의 Spearman 상관분석으로 변수를 선정한 뒤 고정된 Random Forest 모델 하나를 학습하여 최종 Test 성능과 분석 보고서를 생성한다.

## Step 1. 예측용 데이터 구조 및 무결성 검사 구현

- 기존 Train/Val/Test parquet을 합쳐 전체 시계열을 복원한다.
- `(user_id, sample_num, meas_date)`를 개체 관측 키로 사용하고 날짜순으로 정렬한다.
- 개체·날짜 키 중복, 날짜 역전, NULL, `sample_num` 연속성 및 split 날짜 중복을 검사한다.
- 각 행이 어느 raw split에 속했는지 보존한다.
- 사용자·개체별 행 수, 기간, 조사 간격을 정리한 CSV와 manifest를 생성한다.
- 이 단계에서는 변수 가공이나 모델 학습을 하지 않는다.

완료 산출물:

- 개체별 시계열 감사 코드
- `artifacts/data_audit/entity_summary.csv`
- `artifacts/data_audit/interval_summary.csv`
- `artifacts/data_audit/audit_manifest.json`
- 관련 단위 테스트

## Step 2. 개체별 차기 화방수 타깃 및 93개 후보 변수 구현

- 모든 변수는 `(user_id, sample_num)`별로 독립적으로 계산한다.
- 입력 시점 `t`의 다음 관측행을 연결해 다음 항목을 생성한다.
  - `target_date`: 다음 조사일
  - `next_fruit_cluster_num`: 다음 조사 시점의 개체별 화방수
- 개체별 마지막 관측행은 다음 정답이 없으므로 제외한다.
- 다음 11개 기초 신호를 사용한다.
  - `fruit_cluster_num`
  - `leaves_length`, `leaves_num`, `petiole_length`, `theca_diameter`
  - `first_flower_num`, `second_flower_num`, `third_flower_num`
  - `first_fruits_num`, `second_fruits_num`, `third_fruits_num`
- 다음 후보 변수를 생성한다.
  - 현재값 11개
  - 직전값 11개
  - 직전 대비 변화량 11개
  - 최근 최대 4회 평균·누적·최솟값·최댓값·표준편차 55개
  - `days_since_previous`, `days_since_first_measurement`, `week_of_year_sin`, `week_of_year_cos` 4개
  - `rolling_history_count` 1개
- 총 후보 입력 변수는 93개로 고정한다.
- 초기 1~3회 관측은 가용 이력으로 rolling 통계를 계산한다.
- 첫 관측의 직전값은 현재값, 변화량은 0, 표준편차는 0으로 설정하여 NULL을 만들지 않는다.
- 모든 rolling 계산은 현재와 과거 데이터만 사용하고 미래 관측은 사용하지 않는다.

완료 산출물:

- 재사용 가능한 feature engineering 모듈
- 93개 후보 변수 정의 manifest
- 인위적 소형 시계열을 이용한 lag·delta·rolling·target shift 단위 테스트

## Step 3. 예측용 Train/Validation/Test 재구성

- 기존 입력행의 split이 아니라 `target_date`가 속한 raw split을 예측 표본의 split으로 사용한다.
- Train 마지막 시점의 정보로 Validation 첫 화방수를 예측하고, Validation 마지막 시점의 정보로 Test 첫 화방수를 예측하는 것은 허용한다.
- 정답 날짜는 서로 다른 split에 절대 중복되지 않도록 검증한다.
- 식별 및 추적 컬럼은 보존하되 모델 입력에서는 제외한다.
  - 제외: `sn`, `user_id`, `sample_num`, `item_code`, 원본 `meas_date`, `target_date`
- 예상 총 표본 수는 개체별 마지막 행 8개를 제외한 536행이다.
- 예상 분할은 Train 372행, Validation 80행, Test 84행이며 실제 결과와 함께 manifest에 기록한다.
- 모든 후보 변수와 타깃에 NULL·무한값이 없는지 검증한다.

완료 산출물:

- `processed_data/test_candidates.parquet`
- `processed_data/manifest.json`
- 타깃 날짜 기반 경계 및 미래정보 누수 테스트

## Step 4. Spearman 상관분석 및 최종 변수 선정

- 상관계수 계산과 변수 선정에는 Train 데이터만 사용한다.
- 각 후보 변수와 `next_fruit_cluster_num`의 Spearman 순위상관계수를 계산한다.
- 상수 변수와 상관계수가 계산되지 않는 변수는 제외한다.
- `|Spearman ρ| ≥ 0.20`인 변수만 1차 선택한다.
- 선택된 변수를 타깃과의 절대 상관계수가 큰 순서로 정렬한다.
- 이미 유지된 변수와 `|Spearman ρ| ≥ 0.90`이면 중복 변수로 제거한다.
- 중복 쌍에서는 타깃과 절대 상관계수가 더 큰 변수를 유지한다.
- Validation과 Test에는 Train에서 선정된 동일한 변수 목록만 적용한다.

## Step 5. Random Forest 최종 모델 및 평가 구현

- 변수 선택 후 Train과 Validation을 합쳐 최종 모델을 한 번 학습한다.
- 모델은 `RandomForestRegressor`로 고정한다.
  - `n_estimators=500`
  - `max_depth=8`
  - `min_samples_leaf=3`
  - `max_features="sqrt"`
  - `random_state=42`
  - `n_jobs=-1`
- 별도의 모델 비교나 Test 기반 튜닝은 수행하지 않는다.
- Test에서 연속형 예측값을 사용해 다음 지표를 계산한다.
  - MAE
  - RMSE
  - R²
- 전체 Test 성능과 함께 사용자별·개체별 보조 성능을 산출한다.
- 다음 시각화를 생성한다.
  - 실제값–예측값 산점도
  - 개체별 시간순 실제값–예측값 그래프
  - 잔차 분포
  - Random Forest 변수 중요도
- 학습 모델, 최종 변수 순서 및 실행 설정을 저장한다.

## Step 6. 전체 실행 명령과 최종 보고서 통합

- Step 1~5를 순서대로 호출하는 `run_pipeline.py` 진입점을 구현한다.
- 기본 실행은 기존 raw parquet을 사용하며 DB 연결 없이 동작하게 한다.
- 선택적으로 `--rebuild-raw`를 지정할 때만 DB에서 raw split을 다시 생성한다.
- 중간 산출물 디렉터리를 자동 생성하고 각 단계 실패 시 원인을 명확히 출력한다.
- 모든 manifest를 합쳐 데이터 수, 후보 변수 수, 선정 변수, 모델 설정 및 Test 결과를 기록한다.
- 최종 Markdown 보고서에 다음 내용을 자동 작성한다.
  - 데이터와 개체 구성
  - 날짜 기반 분할 정책
  - 93개 후보 변수 정의
  - Spearman 변수 선정 결과
  - 최종 선택 변수 목록
  - Random Forest 설정
  - Test 성능과 그림
  - 데이터 규모 및 일반화 범위에 대한 한계
- README에 설치 요구사항, 실행법, 산출물 위치를 정리한다.

최종 실행 인터페이스:

```bash
python AXData/flower_cluster_prediction/run_pipeline.py
```

DB 원본부터 다시 만들 경우:

```bash

```

최종 성공 기준:

- 전체 명령이 중단 없이 완료된다.
- 예측용 데이터는 8개 개체의 시계열로 구성된다.
- 동일 개체의 미래값이 입력 변수 계산에 사용되지 않는다.
- 예측 표본은 정답 날짜 기준으로 분할된다.
- 후보 변수와 타깃에 NULL 및 무한값이 없다.
- 상관분석은 Train에서만 수행된다.
- Test는 변수 선택·튜닝에 사용되지 않는다.
- 동일 seed 실행에서 동일한 선택 변수와 성능이 재현된다.
- 최종 보고서와 모델·예측값·지표·그림이 모두 생성된다.

## Assumptions

- `sample_num`은 사용자 내에서 동일 개체를 지속적으로 식별한다.
- 예측 간격은 고정 7일이 아니라 해당 개체의 실제 다음 조사 시점이다.
- `user_id`, `sample_num`, `sn`은 추적용으로만 유지하고 모델 입력에서는 제외한다.
- 4회 rolling은 현재 시점을 포함한 과거 방향 window이며 중앙정렬을 사용하지 않는다.
- 목표는 최고 성능 탐색이 아니라 고정된 분석 절차로 개체별 차기 화방수 예측 가능성을 입증하는 것이다.
