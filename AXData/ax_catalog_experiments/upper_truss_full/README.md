# 토마토 20 / 딸기 5화방 전수조합 실험과 순차 배포

사용자 요청(2026-10-20): 기존 데이터로 127개 입력 조합의 1시드 간략실험과 정식 3시드 실험을 병행하고, 완료·검증된 1시드 결과를 먼저 기존 작물 요약 URL에 배포한 뒤 정식 결과로 교체한다.

## 범위·입력

- 토마토 화방개화수 1~20, 딸기 화방착과수 1~5. 작물별 공통 모델이며 화방별 지표를 따로 산출한다.
- 같은 개체·작기·화방의 현재 조사에서 다음 원천 조사값을 예측한다. 현재·다음 값이 유효하고 간격이 1~14일인 동일 조사쌍을 모든 조합에 적용한다.
- `upper_truss_screening`의 원천 정제 절차로 범위를 다시 만들었다. 딸기 6·7화방은 타깃 및 위치·부분합 입력에서 제외된다.
- 화방 번호만 공통 필수 입력으로 둔다. 시설 ID는 입력하지 않는다. E1을 제외한 조합에 현재값·이력을 몰래 포함하지 않는다.
- E1: 현재값·과거 이력·인접 화방·위치·이동. E2: 영양생장 현재·과거 파생값. E3/E4/E5: 내부 환경/외부 기상/근권. E6: 장치 의미 통합 제어. E7: 수치·범주형 작기 맥락.
- 환경·근권은 동결 원천 센서 224,525,909행을 스트리밍 일별 충분통계로 집계해 현재 범위의 모든 조사일에 대해 1/3/7일 창을 재계산한다. E6은 기존 원천 기반 의미 통합 스트림에서 재집계한다. 창은 `[조사일-기간, 조사일)`이다.
- 영양생장은 기존 원천 스냅샷에서 현재·과거 파생값을 다시 구성하고 같은 개체·작기·조사일에 연결한다. 연결 불가값을 임의로 0 처리하지 않는다.
- 폴드 학습 자료만으로 결측·상수·상관·VIF 선별 및 범주 인코딩을 수행한다. 목표 화방 번호는 선별에서 보호한다. 유효 입력 수와 제외 근거를 저장한다.
- 예측값은 음수만 0으로 처리한다. 개화수 상한이나 학습 최대값으로 상한을 강제하지 않는다.

## 학습 횟수와 평가

모델: Poisson, Random Forest, CatBoost, MLP, TabM, TFT.

| 구분 | 1시드 quick | 정식 formal |
|---|---|---|
| 조합 | E1~E7 비어 있지 않은 127개 | 동일 127개 |
| 튜닝 | 기존 간략실험의 고정 예산 | 기존 정식 하이퍼파라미터 격자 |
| 내부 CV | 없음 | 학습시설 내부 시간순 3분할, 경계 너머 정답 제거 |
| 튜닝 시드 | 해당 없음 | 42 |
| 조합 검증 시드 | 42 | 42·52·62 |
| 평가 | 모델별 검증 우승 조합을 Train+Validation 재학습 후 Test | 동일, 3시드 반복 |
| 학습 횟수 | 1,524 검증 + 12 평가 = **1,536회** | 42,672 CV + 4,572 검증 + 36 평가 = **47,280회** |

정식 격자 후보 수는 모델 순서대로 2/12/8/16/16/2개다. “3시드”는 검증·평가 반복이며 모든 내부 CV 후보를 3시드로 돌린다는 뜻은 아니다. 완료 시간을 미리 약속하지 않는다.

조합 및 작물 대표 모델은 Validation pooled RMSE → MAE → 변수 수 → 조합 ID/모델명으로 고정한다. Test를 보고 재선정하지 않는다. 정식 학습 횟수는 CV 최적 epoch 중앙값을 사용한다.

기존 시설 분할을 그대로 사용한다. 범위를 정하는 데 기존 Test 분포와 탐색 결과를 확인했으므로 **새 독립 외부검증이 아니다**. 3시드는 시설 일반화의 증거가 아니다.

## 실행·재개

AXData 작업 폴더 기준:

```bash
PYTHONPATH=.. OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
  ../envs/jslee_py311/bin/python -u -m AXData.ax_catalog_experiments.upper_truss_full.verify_setup
PYTHONPATH=.. OMP_NUM_THREADS=4 MKL_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
  ../envs/jslee_py311/bin/python -u -m AXData.ax_catalog_experiments.upper_truss_full.supervise
```

감독 프로세스는 두 캠페인을 동시에 시작한다. 캠페인별 GPU 작업자 2개·CPU 작업자 1개, 작업자당 호스트 스레드 4개. 기존 다른 실험 프로세스는 종료하지 않는다.

완료된 실행과 조합 요약은 재사용하고, 신경망의 로컬 체크포인트를 보존한다. 데이터 해시·설정·코드 해시가 달라지면 같은 캠페인으로 조용히 재개하지 않는다. 실패한 후보를 누락한 채 완료 처리하지 않으며 자동 게시를 막는다. 원인을 해결한 뒤 실패 기록을 보존·정리하고 같은 명령으로 재개한다.

중복 실행은 파일 잠금으로 막는다. `STOP` 파일 기능은 구현하지 않았으므로 정지 시 이 캠페인의 감독·하위 PID를 확인해야 한다.

상태:

## 완료 후 배포

각 캠페인의 `run → report → publish` 순서가 감독 프로세스에 등록돼 있다.

1. 전체 1,524개 조합 성공 및 선정 조합의 모든 평가 시드 성공 확인.
2. 저장 예측값의 평가 행·정답·유한값·지표·선정 규칙·학습 횟수를 검증.
3. 작물별 네 지표는 **화방별 지표의 동일가중 평균을 시드 간 평균**해 표시. 표준편차는 이 시드별 평균의 표본 표준편차.
4. 화방별 성능·전체 행 성능·기준선·6개 모델·127개 조합을 접힌 영역에 제공.
5. 합계는 모든 대상 화방의 정답이 같은 다음 조사일에 있는 사례만 대상으로 화방별 예측을 합산한다. 합계를 직접 학습한 별도 모델로 표시하지 않는다.
6. 독립 배포 checkout에서 **`ax_data_validation_crop/`만** 커밋·push. 기존 `/ax_data_validation/`은 변경하지 않는다.
7. GitHub Pages 성공 및 공개 `index.html`·`summary.json` 해시 일치를 확인한 뒤 게시 완료로 기록.
8. 두 배포를 잠금으로 직렬화하며, 동일 캠페인의 formal이 게시됐으면 quick으로 되돌리지 않는다. 네트워크 배포 실패는 최대 6회 재시도하고 실패 상태를 남긴다.
