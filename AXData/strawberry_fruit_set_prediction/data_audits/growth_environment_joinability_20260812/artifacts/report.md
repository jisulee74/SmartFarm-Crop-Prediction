# 생육·환경 데이터 결합 가능성 점검

이 분석은 Dataset Split 이전 read-only 정합성 점검이다. Split, 보간, feature 생성,
원본 DB 및 기존 코드 수정은 수행하지 않았다.

## 분석 모집단

- 생육 테이블: `sfkr_pvsn_grow`
- 환경·제어 테이블: `sfkr_hbfm_env_con`
- 시설 매핑: `sfkr_pvsn_id`
- `meas_date >= 2024-05-02`
- 세 착과수 컬럼이 모두 non-NULL인 행
- `0,0,0`은 정상 target
- 동일 target 중복은 한 행 유지
- 충돌 중복이 있는 `user_id + 조사일` 전체 제외

충돌 제외 후 생육행은 6,317개, 조사일은 743개, 사용자는 22명이다.

## ID 집합

- 전체 생육 user_id: 66개
- 전체 환경 facility_id: 65개
- `sfkr_pvsn_id`로 user_id에 매핑 가능한 환경 사용자: 64개
- 공통 user_id: 64개
- 생육에만 있는 ID: `PF_0024694`, `PF_0024698`
- 환경에만 있는 매핑 user_id: 없음
- 매핑되지 않은 환경 facility_id: `PF_0024694_01`

모델 대상 22명은 모두 `user_id + '_01'` 시설에 일대일 연결된다.

## 환경 시간 품질 해석

- 대부분 센서 스트림 평균 간격의 시설별 중앙값은 약 10~13분이다.
- 따라서 5분 슬롯 연속성 중앙값이 약 37~50%인 것은 주로 10분 수집주기 때문이다.
- `user_id + timestamp` 초과행은 여러 센서 동시관측을 포함하므로 데이터 오류 중복으로
  직접 해석할 수 없다.
- 논리 센서 키(`facility_id + fld_code + sect_code + fatr_code + maker_id + sen_id + timestamp`)
  중복도 존재하므로 결합 전에 별도 deduplication 규칙이 필요하다.
- 주요 장기 시설 전체 결측:
  - `PF_0024357`: 2025-01-11~2026-01-26, 381일; 추가 19일
  - `PF_0024688`: 2025-05-02~2025-07-16, 76일; 추가 18일
  - `PF_0023732`, `PF_0023743`: 2025-09-11~09-21, 각 11일
  - `PF_0024651`: 2024-10-17~10-25, 9일

## 작물·시설 식별

- 모델 대상 생육 item_code는 모두 `080400`이다.
- 환경도 모두 `080400`을 포함한다.
- `PF_0000574` 환경에는 `080300`과 `080400`이 함께 있어 item_code 필터가 필요하다.
- `PF_0021351` 환경에는 빈 item_code와 `080400`이 함께 있어 빈 코드 처리 규칙이 필요하다.

## 결론

22개 공통 시설 모두 기술적으로 결합 가능하지만, 동일한 품질로 사용할 수는 없다.
Dataset Split 전에 다음을 해결해야 한다.

1. 환경 데이터의 기본 시간축을 5분으로 가정하지 말고 실제 약 10분 주기를 반영한다.
2. 논리 센서 timestamp 중복 제거 규칙을 확정한다.
3. `PF_0024357`, `PF_0024365`, `PF_0023923`처럼 coverage가 낮은 시설의 포함 기준을 정한다.
4. 장기 결측을 가로질러 보간하지 않는다.
5. 환경 item_code가 혼재하거나 빈 시설에 작물 필터 규칙을 적용한다.
6. Split 전에 필요한 lookback 길이를 확정하고, 그 길이를 완전히 확보한 생육행만 episode 후보로 만든다.

7일 완전 coverage를 필수 조건으로 하면 사용할 수 있는 생육행은 5,197개다.
단순히 과거 환경 데이터가 한 번이라도 있으면 된다는 느슨한 기준은 5,676개지만,
시계열 모델 입력 기준으로는 권장하지 않는다.
