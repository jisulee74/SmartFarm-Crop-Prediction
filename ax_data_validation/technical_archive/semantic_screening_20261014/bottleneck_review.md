# 2026-10-14 정식 실험 병목 점검

- CPU affinity는 72개이지만 컨테이너 `cpu.max`는 `800000 100000`으로 실제 한도는 8코어 상당이다. 이 자원은 컨테이너의 다른 작업과도 공유한다.
- 정식 실험은 CPU 워커 8개와 GPU 워커 4개를 사용했다. BLAS 스레드 제한이 없었고 확인한 워커의 스레드 수는 175개였다.
- 점검 시 CPU pressure some avg60 약 89.7%, I/O 및 메모리 pressure avg60은 0이었다. 이는 CPU 과다 스레드 경쟁이 주요 병목이라는 판단을 뒷받침한다. 호스트/공유 작업의 영향도 포함되므로 특정 모델만의 사용률로 해석하지 않는다.
- 변수 선택 구현에는 제거 때마다 상관계수 행렬을 다시 만들고, VIF를 변수별 최소제곱 회귀로 반복 계산하는 추가 비용이 있다. 이번 작업에서 이 알고리즘이나 실험 정책은 변경하지 않았다.
- OMP/OPENBLAS/MKL/NUMEXPR/BLIS 스레드를 1로 제한해 정식 실행을 재개했다. 확인한 재개 직후 워커의 총 스레드 수는 4개로 감소했다.
- 완료 요약 24개의 SHA-256 및 캠페인 manifest 해시를 재개 전후 비교해 모두 동일함을 확인했다. 완료 fit/checkpoint를 재사용하고 중단된 fit만 재개/재실행한다.
- 재개 후 완료 요약이 24 → 28 → 189개로 증가했다(189개는 10월 14일 11:46경 확인). 최종 완료 시간은 전체 잔여 모델의 실제 처리량을 더 관찰해야 한다.
